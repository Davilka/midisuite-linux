# Clean-room / independent implementation

This project is an **independent reimplementation** of the M-VAVE / SINCO
“Midi Suite” editor for the **SMC-Mixer**, written from scratch in Python for
Linux.

## What “independent” means here

* All source code in this repository was written for this project.  No code
  from the original application is copied, translated, decompiled into source
  or otherwise reused.
* No assets from the original application are distributed: no images, fonts,
  stylesheets, firmware blobs, factory configuration dumps or translation
  files.  The device panel is drawn with simple Qt primitives; the default
  preset is generated by `midisuite.devices.smc_mixer.default_preset()`.
* The application does not call, load or embed the original binaries.
* The specification in [`protocol.md`](protocol.md) is written in terms of
  observable behaviour (packets on the wire, bytes stored in the device,
  reactions of the hardware), not in terms of original source code.

## How the behaviour was established

1. **Wire observation.**  The device was exercised over USB MIDI while the
   traffic was captured.  The framing, the 8→7 bit packing, the checksum and
   the command set were derived from those captures and from the public
   M-VAVE / Cuvave protocol family documentation.
2. **Controlled experiments.**  Single bytes of the configuration were
   changed, written back and the resulting MIDI output and LED behaviour were
   observed.  This is how the message modes, the value bytes and the LED field
   were mapped (see the “Verified” section of `protocol.md`).
3. **Structural analysis.**  The memory layout (two 3141-byte presets, record
   sizes, field order) was confirmed by reading and writing the device and by
   checking invariants (for example the SysEx marker spacing every 71 bytes).

Static inspection of the shipped application was used during the research to
cross-check the protocol (the tooling and findings are described in
`protocol.md`).  The implementation itself, however, is written against the
documented behaviour and the hardware, and can be maintained without the
original binary.
